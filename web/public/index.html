Home Assistant Voice PE

Say “Okay Nabu.” Your Companion answers.

Connect the Home Assistant Voice Preview Edition to a Companion that runs on your own hardware. It speaks through your local model, draws on your Companion Memory, and keeps every word in your house.

Start setup See how it connects

How your voice travels

The Voice PE hears the wake word on the device and streams your request to Home Assistant. Home Assistant hands it to the Companion voice bridge, which asks ci-server for a transcript, an answer and a spoken reply.

  1. Voice PE Wake word, mics, speaker
  2. Home Assistant Assist Runs the voice pipeline
  3. Voice bridge Wyoming, port 10700
  4. ci-server OpenAI-compatible API, port 8080
  5. Ollama and speech Local model, Whisper, Kokoro Companion Memory Recall and save each exchange
Latency target
Under 2 s from end of speech to first word
Where it runs
Any Mac, PC or Linux box on your network
What leaves the house
Nothing, unless you choose OpenAI speech

When something is off

      

        

          Home Assistant says it cannot connect
          
Wyoming is plain TCP, not a web address. Enter only the IP and port 10700, and make sure no firewall blocks it. From the Home Assistant host, nc -vz <ip> 10700 should succeed.

        

        

          The Voice PE lights up but never answers
          
Run the check above. A red language model row usually means the model is not pulled yet: docker compose -f compose.yml exec ollama ollama pull llama3.2.

        

        

          Speech-to-text returns nothing
          
If you chose local speech, download the models once (the two curl lines in step 3). If you kept Home Assistant speech, pick faster-whisper and Piper in the pipeline instead of the companion ones.

        

        

          Answers do not use my memory
          
The key needs the memory scope, and the address must include /api when you reach Companion Memory through its gateway. The check shows the exact error.

        

        

          The check here fails but curl works
          
Browsers block an https page from calling a plain http address on your network. Serve ci-server over https with Tailscale Serve or a Cloudflare Tunnel, or trust the curl result.
